## 本期三个核心概念

1. **Before Hook(前置钩子)** — 工具执行**前**运行的回调:可以拦截(block,后面的钩子和 execute_tool 都不跑)也可以改写(rewrite,参数以改后为准)
2. **After Hook(后置钩子)** — 工具执行**后**运行的回调:只观察不干预,拿到的结果就是最终结果,负责审计、统计、落盘
3. **审计日志(audit_log.jsonl)** — Agent 行为的"行车记录仪":每次工具调用追加一行 JSON,三态 `ok` / `masked` / `blocked`——被拦的恰恰最值得记录

## 钩子链三步

```
① Before 拦截型  _hook_sensitive_guard   工具∈保护名单 + 命中敏感词 → blocked
② Before 改写型  _hook_sensitive_masker  其余工具命中 → 参数打码(sk-*** →)放行
③ After  观察型  _hook_audit_logger      不拦不改,记录 {tool, args, result, status, duration_ms}
```

> 保护名单(6 个"落盘/外发"工具):save_user_profile / mcp_call_tool / send_message / broadcast_message / dispatch_subagent / dispatch_subagents_parallel——数据要写盘或出门的,硬拦截;其余工具只打码。

## 没有 Hooks vs 有 Hooks:完整对比

| 维度 | 裸奔(第 11 期) | 有 Hooks(本期) |
|---|---|---|
| 调用流程 | tool_call → execute 直通 | tool_call → Before → execute → After |
| 敏感数据 | 照存、照发,无人过问 | 落盘/外发拦截,普通工具打码 |
| 安全策略 | 没有或散落各工具函数里 | 集中在钩子链,22 个工具统一生效 |
| 出事后回放 | 无凭无据 | audit_log.jsonl 三态全记录 |
| 加一条策略 | 改核心代码 | HOOKS 注册表加一个函数 |
| 拦截的表达 | (无) | 组装成工具结果还给 LLM,带 reason/hint |
| 对 MCP 外接工具 | 裸奔 | 同样过安检(挂载点全局唯一) |

## 一行代码记住本期

```python
# 工具循环里的挂载点:三行,给 22 个工具装上安检
blocked, fn_args, hook_note = run_before_hooks(fn_name, fn_args)  # ① 拦截/改写
if not blocked:
    result = execute_tool(fn_name, fn_args)                       # ② 真执行
run_after_hooks(fn_name, fn_args, result, status, duration_ms)    # ③ 审计落盘
```
