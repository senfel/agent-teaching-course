## 本期三个关键动作

1. **维护 messages 列表** — 每轮把 user + assistant 都加进去
2. **回灌历史调用 API** — 传完整 messages,模型就能看到上下文
3. **超 10 轮截断最早** — 简单截断,防止历史无限膨胀

## 一行代码记住本期

```python
messages.append({"role": "assistant", "content": answer})  # ← 回复也加回历史
```

> 把模型回复也加入 messages,下一轮调用时它就"记住"了。

## token 增长对比

| 轮次 | 第 02 期 prompt | 第 03 期 prompt |
|---|---|---|
| 第 1 轮 | ~10 | ~10 |
| 第 2 轮 | ~10 | ~30(含第 1 轮) |
| 第 5 轮 | ~10 | ~150(含前 4 轮) |

> 历史越多 token 越贵——这就是上下文长度问题的由来。

## 上下文长度限制策略

```
MAX_ROUNDS = 10  # 1 轮 = 1 user + 1 assistant

超 10 轮 → 删掉最早的一轮(每轮 2 条)
保留最近 10 轮 → 简单粗暴,但有边界
```

> 第 07 期升级为 compact 压缩(摘要旧对话,而非直接删)。

## 三期演进

| 期 | messages 内容 | 记忆 |
|---|---|---|
| 01 | 只传当前一句 | 无 |
| 02 | 只传当前一句(故意暴露痛点) | 无 |
| **03** | **完整对话历史** | **有** |

## 一句话总结

> 模型本身无记忆,记忆是你用 messages 列表"喂"给它的——把历史塞进去,它就"记住"了;但历史不能无限长,超限时截断最早。
