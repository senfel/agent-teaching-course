## 本期三个核心概念

1. **MCP 协议** — Model Context Protocol,连接"外部工具服务器"的开放协议。工具跑在别人的进程里,Agent 连上就能用,不抄代码、不重启
2. **stdio transport** — MCP 的第一种传输方式:把子进程的 stdin/stdout 当"电话线",每行一条 JSON 消息,不用网络端口
3. **JSON-RPC 2.0** — MCP 的消息格式:请求带 `id`,响应回同一个 `id`;没有 `id` 的是通知(不用回)

## 协议三步

```
① 握手   initialize          → 互报身份/协议版本 → 回 initialized 通知
② 拿工具 tools/list           → 服务器交出 [名称 + 描述 + inputSchema]
③ 调工具 tools/call           → 传 name + arguments → 收 content 数组
```

> inputSchema 和内置工具的 function schema 同构——学过第 05 期,服务器端的 schema 一眼就懂。

## 四个新工具

```python
# ① 查看有哪些 MCP 服务器可连接
list_mcp_servers()
# → {mcp_servers: [{server_id: "repo", connected: false, tool_count: 3}, ...]}

# ② 连接服务器(启动子进程 + 握手 + 拉取工具清单)
mcp_connect(server_id="repo")
# → {server: "repo", status: "connected", tools: [{name, description}, ...]}

# ③ 列出服务器提供的工具(名称 + 描述 + 参数 schema)
mcp_list_tools(server_id="repo")

# ④ 统一入口:调用服务器上的任意工具
mcp_call_tool(server_id="repo", tool_name="get_repository_info",
              arguments={"owner": "deepseek-ai", "repo": "DeepSeek-R1"})
```

> 4 个工具和前 16 个完全平等——都走第 05 期的工具循环,一行没改。

## 内置工具 vs MCP 工具:完整对比

| 维度 | 内置工具(第 05 期) | MCP 工具(本期) |
|---|---|---|
| 工具住哪 | Agent 进程里的函数 | 外部服务器进程里 |
| 加工具 | 改源码 + 注册 schema + 重启 | 注册表加一条连接命令 |
| 通信方式 | 进程内直接调用 | 跨进程 stdio JSON-RPC |
| 谁维护 | 自己写、自己维护 | 别人写、拿来就用 |
| 换供应商 | 重写工具函数 | 换 command 启动命令 |
| 对 LLM 的暴露 | 每个工具一个 schema | 统一走 mcp_call_tool |
| 生命周期 | 常驻 | 连接/断开随需 |

## 一行代码记住本期

```python
# 协议三步:握手 → 拿工具 → 调工具
result = self._request("initialize", {...})           # ① 握手
self._send({"jsonrpc": "2.0", "method": "notifications/initialized"})
self.tools = self._request("tools/list").get("tools")  # ② 拿工具
result = self._request("tools/call",                   # ③ 调工具
                       {"name": tool_name, "arguments": arguments})
texts = [c["text"] for c in result["content"]]         # 结果统一装在 content
```
