# 第 06 期 · 知识卡片:Skills 按需加载

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│    给 Agent 配一个"技能库"——平时只记目录,用到才翻手册      │
│                                                             │
│   ┌─────────────────────────────────┐                       │
│   │ skills/                         │                       │
│   │  ├─ weather/SKILL.md     ─┐     │  ← 技能库             │
│   │  └─ git-cheatsheet/SKILL.md─┐   │    (全文在磁盘)      │
│   └────────────────────────----|--─┘                       │
│                               │     │                       │
│      第一级(启动时)          ▼     │  第二级(按需)       │
│   ┌─────────────────────────────┐   │                       │
│   │ 只解析 frontmatter:        │   │                       │
│   │  weather: 查天气...        │   │                       │
│   │  git-cheatsheet: Git 问题..│   │                       │
│   │  → 追加到 system prompt 尾 │   │                       │
│   └─────────────────────────────┘   │                       │
│        索引常驻(几百 token)        │                       │
│                               ▼     ▼                       │
│   user: "Git 怎么撤销提交?"                                │
│     → 模型看索引,自己决定调 load_skill("git-cheatsheet")   │
│     → tool 消息注入 SKILL.md 全文(本轮才付 token)          │
│     → 按手册回答: git reset --soft HEAD~1                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 本期三个关键概念

1. **SKILL.md frontmatter** — `name` + `description` 两个必填字段;description 写"什么时候用",是模型的路由依据
2. **两级加载** — 索引(name + description)常驻 system prompt;全文由模型调 `load_skill` 工具按需注入
3. **知识注入** — 技能全文走 `tool` 消息进历史,随回灌可见、随截断自愈(需要时模型会再调一次)

## 交互命令(累积式)

| 命令 | 引入期 | 作用 |
|---|---|---|
| `quit` | 01 | 退出,打印 token 汇总 |
| `reset` | 03 | 清空历史(人设和技能索引保留) |
| `history` | 03 | 打印 messages 列表 |
| `soul` | 04 | 查看人设(本期起尾部含技能索引) |
| `tools` | 05 | 查看已装工具(JSON schema) |
| `skills` | **06** | 查看技能索引(全文未加载) |

> 输入 `history` 能看到技能加载的痕迹:assistant 带 tool_calls(load_skill) → tool 携带 SKILL.md 全文 → assistant 最终回答。

## 一行代码记住本期

```python
system_prompt = soul + build_skills_prompt(load_skills_index())
# 索引常驻 system prompt;全文等模型自己调 load_skill 工具再注入
```

> load_skill 就是个普通工具,完全复用第 05 期的工具循环——循环代码一行没改,这是累积式的红利。

## 两级加载流程

```
启动: 扫描 skills/*/SKILL.md → 只取 frontmatter → 索引注入 system prompt
                                          ↓
user: "Git 怎么撤销上次提交?"
  ↓ 第 1 次调用 API(模型看到索引)
assistant: tool_calls=[load_skill(name="git-cheatsheet")]   ← 模型自己决定
  ↓ 执行: 读 SKILL.md 全文
tool: {"skill": "git-cheatsheet", "content": "# Git 速查..."} ← 全文注入
  ↓ 第 2 次调用 API
assistant: "用 git reset --soft HEAD~1……"                   ← 按手册回答
```

## token 账本:为什么"索引 + 按需"是对的

| 方案 | 2 个技能 | 20 个技能 | 200 个技能 |
|---|---|---|---|
| 全量塞 system prompt | ~1K token | ~10K token | 爆上下文 |
| **Skills 两级加载** | 索引 ~100 | 索引 ~500 | 索引 ~4K |

> 全量方案每轮都付、90% 的对话用不上;Skills 方案只付索引的钱,全文只在用到的轮次付一次。

## SKILL.md 设计三原则

1. **description 写"什么时候用"** — "Git 命令速查" ✗ / "当用户问怎么撤销提交时使用" ✓
2. **正文写给模型看** — 多用表格和步骤,少用散文,冗余文字浪费 token
3. **写清边界** — "不编造小时级预报"这类约束句,防止技能被滥用

## 本期两种技能形态

| 技能 | 形态 | SKILL.md 里装什么 |
|---|---|---|
| `weather` | 流程型 | 使用流程 + 模拟规则 + 回复模板 + 边界 |
| `git-cheatsheet` | 知识型 | 速查表本身,加载即答案(学员亲手写) |

## 六期演进

| 期 | messages 结构 | Agent 能力 |
|---|---|---|
| 01 | `[user]` | 单次调用 |
| 02 | `[user]`(每次独立) | 循环对话(无记忆) |
| 03 | `[user, assistant, ...]` | 有短期记忆 |
| 04 | `[system, user, assistant, ...]` | 有记忆 + 有身份 |
| 05 | `+ assistant(tool_calls) / tool` | + 有工具(会动手) |
| **06** | **同 05,system 尾部 + 技能索引** | **+ 技能库(能力可扩展)** |

## 一句话总结

> 能力是无限的,上下文是有限的。Skills 用"索引常驻 + 全文按需"化解这对矛盾——加技能 = 加目录,代码零改动,这就是 Agent 的可扩展性。
