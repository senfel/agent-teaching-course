## 本期三个关键概念

1. **JSON Schema 描述工具** — 告诉模型:有哪些工具、叫什么、做什么、需要什么参数
2. **工具循环** — 模型决定调用 → 执行 → 结果喂回去 → 生成最终回答(可能多次调用)
3. **tool 角色消息** — `role: tool` 携带工具结果,被纳入历史回灌

## 交互命令(累积式)

| 命令 | 引入期 | 作用 |

| `quit` | 01 | 退出,打印 token 汇总 |

## 一行代码记住本期

```python
response = client.chat.completions.create(
    model=MODEL, messages=messages,
    tools=TOOLS, tool_choice="auto",  # ← 告诉模型有哪些工具,让它自己决定
)
```

> 模型看到 tools 的 JSON schema,决定"调工具"还是"自己答"。调了就执行,结果喂回去再调一次。

## 工具循环流程

```
user: "现在几点?"
  ↓ 第 1 次调用 API (tools=TOOLS, tool_choice=auto)
assistant: tool_calls=[get_current_time()]    ← 模型说"我要调工具"
  ↓ 执行工具: datetime.now()
tool: {"datetime": "2026-08-14 15:30", ...}   ← 结果喂回去
  ↓ 第 2 次调用 API (带着工具结果)
assistant: "现在是 15:30,周四。"              ← 最终回答
```

> 不再是"一问一答"单次调用,而是循环——模型先说"我要调工具",执行后喂回去,再生成最终回答。

## messages 角色演进

| 期 | messages 角色 | Agent 能力 |
|---|---|---|
| 01 | user | 单次调用 |
| 02 | user(每次独立) | 循环对话(无记忆) |
| 03 | user / assistant | 有短期记忆 |
| 04 | system / user / assistant | 有记忆 + 有身份 |
| **05** | **+ assistant(tool_calls) / tool** | **有记忆 + 有身份 + 有工具** |

> 多了两种新角色:assistant 消息可携带 tool_calls,tool 消息携带工具执行结果。

## tool_choice 参数

| 值 | 行为 | 场景 |
|---|---|---|
| `auto` | 模型自己决定要不要调 | 默认,最常用 |
| `none` | 禁止调工具 | 纯聊天,省 token |
| `required` | 强制调工具 | 必须动手,不能只动嘴 |

## 安全性:工具执行是代码边界

```
危险: eval(expression)           ← 模型传入恶意表达式,任意代码执行
安全: ast.parse → _safe_eval      ← 只允许四则运算节点,拒绝其他
```

> 模型传来的参数不可信!execute_tool() 是代码边界,必须当作用户输入来校验。

## 五期演进

| 期 | messages 结构 | Agent 能力 |
|---|---|---|
| 01 | `[user]` | 单次调用 |
| 02 | `[user]`(每次独立) | 循环对话(无记忆) |
| 03 | `[user, assistant, ...]` | 有短期记忆 |
| 04 | `[system, user, assistant, ...]` | 有记忆 + 有身份 |
| **05** | **`[system, user, assistant+tool_calls, tool, assistant, ...]`** | **有记忆 + 有身份 + 有工具** |

## 一句话总结

> Agent = LLM + 记忆 + 人设 + 工具。前 04 期搞定了前三个,本期用 JSON schema 描述工具、用工具循环让模型"动手"——不再靠"猜",而是调用真实工具获取准确信息。
