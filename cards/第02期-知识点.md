## 本期三个关键动作

1. **while 循环** — 把一问一答串成连续对话的形式
2. **故意不传 history** — messages 里永远只有当前一句
3. **token 计数可视化** — 读 `response.usage`,看到上下文是空的

## 一行代码记住本期

```python
messages=[{"role": "user", "content": user_input}]   # ← 只有这一句
```

> 模型看不到上一句,不是因为它笨,是因为你根本没发给它。

## token 三字段

| 字段 | 含义 |
|---|---|
| `prompt_tokens` | 输入(你发的) |
| `completion_tokens` | 输出(模型回的) |
| `total_tokens` | 合计 |

> 本期每次 prompt 都很小(一句话);下期加 history 后会越滚越大——上下文长度问题浮现。

## 本期埋的伏笔

| 现象 | 后面哪期解决 |
|---|---|
| 问"我姓什么"答不上来 | 第 03 期 history |
| 输入 `reset` 提示"尚未实现记忆" | 第 03 期真正实现 reset |
| prompt_tokens 一直很小 | 第 03 期加历史后对比 |

## 一句话总结

> "连续对话"是客户端伪造的幻觉——你维护一份历史,每次一起发过去,模型就"记得"了。本期先看见问题,下期再动手。
