## 本期三个核心概念

1. **目标契约(GOAL_STATE)** — 模糊目标的"结构化改写":goal(做什么)+ success_criteria[](怎么算完成,可逐条判定)+ max_rounds(预算轮数)+ status(in_progress/done/blocked/failed)+ checkpoints[](自评历史)。契约是循环的锚
2. **控制循环(run_goal_loop)** — 外层 while:订约 → 执行一轮 → check_goal → 看状态。done 停(达标)、blocked 停(止损)、failed 停(做不成/预算耗尽)。预算跑完仍 in_progress → 强制标记 failed(封顶止损)
3. **checkpoint(check_goal)** — 每轮结束对照验收标准如实自评,落盘 `memory/goal_log.jsonl`。过程可回放,失败可复盘 —— 第 12 期审计日志在"任务维度"的延续

## 契约状态机

```
             ┌──────────────┐
 set_goal    │ in_progress  │◀──── check_goal(未达标,继续)
 ───────────▶│   (推进中)   │
             └──────┬───────┘
          ┌─────────┼─────────┐
          ▼         ▼         ▼
        ┌────┐  ┌────────┐ ┌────────┐
        │done│  │blocked │ │ failed │
        └────┘  └────────┘ └────────┘
        达标停   缺前置条件  做不成/预算耗尽
        正常完成 提前止损    封顶止损
```

## 三个新工具(25 → 28)

```python
# ① 订契约:模糊目标 → 结构化验收单
set_goal(goal="产出 README 逐节优化方案",
         success_criteria=["覆盖全部小节", "每条建议附理由"],  # 可判定,不写"更好"
         max_rounds=3)                                        # 预算硬上限

# ② 打 checkpoint:对照验收标准如实自评
check_goal(assessment="第1条达标,第2条还差安装节的理由",
           new_status="in_progress",   # done/blocked/failed/in_progress
           evidence="方案已写到回复中,共 7 节")

# ③ 查看目标进度
goal_status()
# → 契约 + 每轮 checkpoint + 剩余预算轮数
```

## 目标契约 vs TodoList(最容易混)

| 维度 | TodoList(第 08 期) | 目标契约(本期) |
|---|---|---|
| 管理粒度 | 一轮对话内的步骤顺序 | 跨轮次的完成判定 |
| 回答的问题 | "这轮先做什么后做什么" | "几轮之后,什么时候算完" |
| 停止条件 | 清单勾完(单轮内) | 验收达标 / 受阻 / 预算耗尽 |
| 类比 | 施工排期表 | 甲方验收单 |

> 两者配合:每轮用 TodoList 排步骤干活,用 check_goal 向"甲方"(契约)汇报。

## 没有 vs 有:完整对比

| 维度 | 被动应答(第 13 期) | 目标驱动(本期) |
|---|---|---|
| 模糊目标 | 泛泛而谈("可以从以下几方面…") | 订契约,验收标准逐条判定 |
| 多轮任务 | 用户在场盯着,一轮轮追问 | 控制循环自主推进,用户只看 checkpoint |
| 停止条件 | 没有:烂尾或烧穿 | 三种停:达标 / 受阻止损 / 预算封顶 |
| 讨好型人格 | "做完了吗?"→"做完了"(可能没做完) | 自评必须如实,对照验收标准 |
| 过程可观测 | 只有对话记录 | goal_log.jsonl 每轮自评可回放 |
| 成本可挖 | 无上限 | max_rounds 硬上限 + cost_report 对账 |

## 一行代码记住本期

```python
# 外层控制循环:订约 → 执行 → 自评 → 判停
while goal["status"] == "in_progress" and round_no <= goal["max_rounds"]:
    answer = chat_with_tools(control_message)   # 内层:工具循环干活
    check_goal(assessment, new_status)          # 每轮必打 checkpoint
    round_no += 1                               # 预算烧完 → failed 封顶止损
```

## 一句话总结

> 前 13 期管"能力和约束",第 14 期管"方向和停止"—— set_goal 把模糊目标订成可判定的验收单,run_goal_loop 外层循环拿着契约自主推进,check_goal 每轮如实自评并落盘,结束时再对照契约逐条交出最终验收报告。达标停、受阻止损、预算封顶:敢于放手的底气,来自契约和预算,不来自运气。
