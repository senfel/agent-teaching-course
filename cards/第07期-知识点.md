## 本期三个关键概念

1. **三层记忆** — 短期(messages)/ 长期(USER.md)/ 原始历史(JSONL),对应人脑的 WM / LTM / 事件日志
2. **Agent 自己改画像** — `save_user_profile` 是普通工具,Agent 判断"偏好变了"就调,按 section 替换章节内容
3. **Compact 自动压缩** — 轮数超阈值(`COMPACT_THRESHOLD_ROUNDS=8`)→ 用 LLM 把早期对话压成一段摘要,保留最近 `MAX_ROUNDS=10` 轮,腾上下文不丢关键信息

## 三个记忆函数

```python
# ① 加载用户画像(启动时)
profile = load_user_profile()  # 读 templates/USER.md
system_prompt = soul + skills_prompt + "\n\n# 用户画像\n\n" + profile

# ② save_user_profile(Agent 调,写入持久化)
execute_tool("save_user_profile", {
    "section": "稳定偏好",
    "new_content": "- 包管理:uv(替代 pip + venv)\n- Python 版本:3.12"
})

# ③ compact_history(超轮时,自动触发)
if rounds > COMPACT_THRESHOLD_ROUNDS:
    messages = compact_history(messages)  # LLM 摘要 + 保留最近 MAX_ROUNDS=10 轮
```

> 所有记忆工具和第 05-06 期的 get_current_time / calculate / load_skill **完全平等**——加能力 = 加工具,核心循环一行没改。

## 事件溯源纪律

唯一入口 `append_and_persist(messages, msg, session_id, source="produced")`:

| 触发点 | 调它的事件 | source |
|---|---|---|
| 用户输入 | `append_and_persist(messages, {"role":"user", ...})` | `"produced"` |
| assistant tool_call | `append_and_persist(messages, assistant_msg)` | `"produced"` |
| tool 结果 | `append_and_persist(messages, tool_msg)` | `"produced"` |
| assistant 最终回答 | `append_and_persist(messages, final_msg)` | `"produced"` |

**不调它的入口**:trim / compact / reset / quit(它们只重组 messages,不写盘)

**会话元数据 upsert**:每轮对话后调 `log_session()`,Ctrl-C 也保留上一轮快照

**source 字段意义**:默认 `"produced"`(对话产生)。为未来"导入历史 / 重放"留口子——审计时能区分"真用户说的话"和"导入的数据"。

## session_id 三种模式(仅作审计标签)

```python
# 模式 1(默认):每次启动独立
session_id = f"auto-{datetime.now():%Y%m%d-%H%M%S}"

# 模式 2(跨启动接续):同名复用
os.environ["AGENT_SESSION"] = "project-x"
session_id = "project-x"

# 模式 3(项目内开新轮):同名 + UUID 后缀
os.environ["AGENT_SESSION"] = "project-x"
os.environ["AGENT_SESSION_RESET"] = "1"
session_id = f"project-x-HHMMSS-{uuid.uuid4().hex[:6]}"
```

⚠️ 本期 session_id 只影响 raw_history.jsonl 里的 `session` 字段,**不**实现真正的会话续接——想做"自动注入历史 messages"需要按 session 隔离 raw_history + 启动时加载(下一阶段能力)。

## 三层记忆的写入策略

| 层 | 介质 | 写入方式 | 触发 |
|---|---|---|---|
| 短期 | messages[] | 覆盖(trim/compact) | 自动 |
| 长期 / 画像 | USER.md | **替换章节**(section replace) | Agent 调工具 |
| 原始历史 | raw_history.jsonl | **append**(JSONL) | 每轮退出 |

> "为什么是替换而非 append?"——同主题(代码风格)只能有一个权威版本,append 会让 USER.md 出现两个矛盾描述。

## token 账本:为什么三层要分开

| 方案 | 1 个会话 | 跨会话重启 | 审计/回溯 |
|---|---|---|---|
| 只用 messages | ✓ | ✗ 全忘 | ✗ |
| 只用 JSONL 全量回灌 | ✗ token 爆 | ✓ | ✓ |
| 只用 USER.md | ✗ 无细节 | ✓ | ✗ |
| **三层组合** | **✓** | **✓** | **✓** |

> 各取所长,短期管"上下文",长期管"身份",原始历史管"日志"——和人脑三类记忆分工一致。

## 短期 vs 长期 vs 原始历史

| 维度 | 短期(messages) | 长期(USER.md) | 原始历史(JSONL) |
|---|---|---|---|
| 写入 | 自动覆盖 | Agent 调工具替换章节 | 退出时 append |
| 读入 LLM | 全部 | 启动时拼到 system prompt | **不进 LLM** |
| 生命周期 | 会话内 | 永久 | 永久(只增) |
| 主要用途 | 当前对话上下文 | 跨会话身份/偏好 | 审计/回溯/未来训练 |
| 大小限制 | MAX_ROUNDS=10 轮 | 几百字到几 KB | 无限制(append) |

> 关键洞察:**进 LLM 上下文的只有短期+长期**,原始历史只是磁盘日志——千万别把 JSONL 全文回灌,token 必爆。
