## 本期三个关键概念

1. **三状态机** — pending → in_progress → completed,每个任务有个明确状态,不模糊
2. **双约束:顺序 + 单 in_progress** — 工具层面强制执行:必须按 ID 顺序逐个推进(不能跳过),且同一时刻只能有一个 in_progress
3. **外显工作记忆** — 把"我在做什么"从模型脑子里搬到代码数据结构里,面板打印,用户也能看

## TodoList 的三层架构

```
┌───────────────────────────────────────────────────┐
│  ① 提示词层(软约束)                              │
│  todo_guide.md → 注入 system prompt               │
│  引导:"每轮先查 todo_list,需要用户信息就停下"    │
│  拦不住:模型自己编内容标完成                     │
├───────────────────────────────────────────────────┤
│  ② 工具层(硬约束)                                │
│  todo_create / todo_update / todo_list            │
│  双约束硬编码:跳过→返回错误,并行→自动退回       │
│  拦不住:模型编造任务内容                         │
├───────────────────────────────────────────────────┤
│  ③ 工具循环(第 05 期复用)                        │
│  while True: LLM 决定调什么 → 代码执行 → 结果回灌 │
│  模型是驾驶员,工具是车,提示词是交通规则          │
└───────────────────────────────────────────────────┘
```

| 层 | 职责 | 能拦住 | 拦不住 |
|---|---|---|---|
| 提示词层 | 引导行为 | 不查 todo_list | 编内容标完成 |
| 工具层 | 强制规则 | 跳过、并行 | 编造任务内容 |
| 工具循环 | 驱动交互 | — | — |

> 三层缺一不可。硬约束保下限,软约束拉上限。

## 三个新工具

```python
# ① 创建任务(Agent 收到复杂任务时先调)
execute_tool("todo_create", {
    "tasks": ["收集本周工作要点", "整理待讨论议题", "写周报草稿"]
})
# → 返回 [{id:1, content:"...", status:"pending"}, ...]

# ② 更新状态(开始做时调,双约束在这里)
execute_tool("todo_update", {"task_id": 1, "new_status": "in_progress"})
# → 顺序约束拦住"跳过",单 in_progress 拦住"并行"

# ③ 查看进度
execute_tool("todo_list", {})
# → 返回 {total:3, pending:2, in_progress:1, completed:0, tasks:[...]}
```

> 三个工具和第 05-07 期的工具完全平等——加能力 = 加工具,核心循环一行没改。

## 一行代码记住本期

```python
# 约束 1(顺序):前面的任务必须全部 completed 才能开始
# 约束 2(单 in_progress):同时只能一个 in_progress,设新的自动退旧的
if new_status == "in_progress":
    # 顺序检查
    blocked_by = [t["id"] for t in _todo_list if t["id"] < task_id and t["status"] != "completed"]
    if blocked_by: return f"顺序约束:前面还有未完成任务 {blocked_by}"
    # 单 in_progress
    for t in _todo_list:
        if t["status"] == "in_progress": t["status"] = "pending"  # 自动退回!
```
