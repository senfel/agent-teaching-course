前 03 期你的 Agent 有记忆但没身份,问它"你是谁"它就背一大段公司介绍。
这一期,用 templates/SOUL.md 给它戴上"技术助理 Alex"这顶帽子。

CONTRAST
02 / 10

同一个问题 · 有无 system prompt 的差异

🤖 无 system prompt

问: 你好,你是谁?

答: 我是由 XX 公司训练的大语言模型,我可以帮你写文章、翻译、写代码、回答问题、创作诗歌...

通用、客套、什么都接、废话多

🤖 有 system prompt(Alex)

问: 你好,你是谁?

答: 我是 Alex,技术助理。擅长 Python、后端架构、Agent 开发。有什么技术问题直接说。

简洁、务实、聚焦技术、有边界

同一个模型,只是 messages 里多了一条 system 消息,回答风格完全不同——这就是"人设"的约束力。不是改了模型,是给模型加了边界。

FORMULA
03 / 10

有身份的 Agent
messages[0] = {"role": "system", "content": "你是 Alex,技术助理..."} ← 人设(全局指令)
messages[1] = {"role": "user", "content": "你是谁?"}
messages[2] = {"role": "assistant", "content": "我是 Alex..."}

模型在训练时就学会了"听从 system 指令"——role:system 的消息被当成全局指令,优先级高于普通 user 消息。就像给模型戴了一顶"帽子",戴着这顶帽子,它就不是通用助手了。

STEPS
05 / 10

本期 3 个动作

  1. 写人设文件 — templates/SOUL.md,定义 Alex 的角色、能力边界、回答风格
  2. 加载为 messages[0] — {"role": "system", "content": ...},全程约束每次调用
  3. 截断时保护 system — trim_history 跳过 messages[0],人设永不被删

第 1 步是内容:把"Alex 是谁"写清楚。第 2 步是注入:system 消息作为列表第一条。第 3 步是保护:第 03 期的截断逻辑要改一下,跳过 system 只删对话。三步都不复杂,但叠起来就让 Agent 有了"出厂设置"。

CODE
07 / 10

核心代码 · 加载并注入 system prompt

# 人设文件路径
SOUL_PATH = Path(__file__).parent.parent / "templates" / "SOUL.md"

def load_system_prompt() -> str:
    return SOUL_PATH.read_text(encoding="utf-8")

# messages 第一条永远是 system prompt
messages: list[dict] = [
    {"role": "system", "content": system_prompt}
]

关键:把人设从外部文件加载,作为 messages[0] 注入——每次调用模型都先读 system。

人设放外部文件的好处:改人设不用改代码,非技术人员也能改。这是项目里第一个运行时资源文件。

WHY
08 / 10

截断逻辑 · 保护 system 不被删

第 03 期

messages 从头删:

# 超轮时从头删
return messages[cut:]

无 system,直接从头删没问题

第 04 期

跳过 system,只删对话:

has_system = messages[0]["role"] == "system"
system_msg = [messages[0]] if has_system else []
convo = messages[1:] if has_system else messages[:]
return system_msg + convo[cut:]

system 永远在第一条,Alex 永不丢身份

无论聊多少轮,人设永远在 messages[0]

如果不改这个逻辑,聊超过 10 轮后 system 就被删了,Alex 会"失忆"变回通用助手。

TRY IT
09 / 10

试一试 · 5 个动手实验

  • 对比演示 — 程序启动会自动对比"你是谁"的回答差异
    有 system 时模型自称 Alex、风格务实
  • 问非技术问题 — 故意问"帮我写首诗"或"心情不好怎么办"
    看 Alex 怎么礼貌引导回技术话题
  • 输入 soul — 打印当前加载的人设内容
    直观看到 SOUL.md 长什么样
  • reset 后再聊 — reset 只清空对话,Alex 的人设还在
    对比第 03 期的 reset 行为差异
  • 思考题 — 人设文件很长会占多少上下文?怎么平衡详细度和成本?
    后续第 07 期记忆系统会涉及

学完这一期,你的 Agent 有记忆 + 有身份。但它还是只能"说"——不会查时间、不会调接口。下一期给它装第一个工具。
