前 11 期 Alex 的能力越来越强,但每次工具调用都"照单全收"。
这一期给工具循环装一道"安检":敏感词拦截、参数打码、操作审计,全部 Hook 进来。

CONCEPT
02 / 10

没有 Hooks vs 有 Hooks —— 工具调用从"裸奔"到"安检"

🚪 没有 Hooks(第 11 期)

LLM 发起 tool_call → 直接 execute_tool
中间没有任何检查站

让存密钥就存密钥,让外发就外发

事后想查"它到底干了什么"?没有日志,只剩聊天记录

🛡️ 有 Hooks(本期)

Before 钩子先过一道:可拦截、可改写
After 钩子再补一道:只观察、只落盘

敏感词进"落盘/外发"工具 → blocked

普通工具带敏感词 → 参数打码后放行,每次调用都进审计日志

Hook = 挂在工具调用"前后"的回调函数,能力越强,越需要约束

类比机场安检:旅客(LLM 的 tool_call)再急也要过安检门(Before Hook),行李(参数)可疑可以重新打包(打码),全程有监控录像(After Hook 审计)。

FORMULA
03 / 10

工具调用的安检流水线

tool_call
LLM 发起调用
→
Before
钩子链:拦截 / 改写
→
execute
真正执行工具
→
After
钩子链:审计落盘

任何 Before Hook 说 block 就短路;改写的话参数以改后为准

三态status含义
ok"ok"钩子没动过,参数原样执行
masked"masked"参数被 Before Hook 打码后放行
blocked"blocked"被拦截,工具压根没执行

被拦截不是抛异常——组装成一条正常的工具结果(带 reason 和 hint)还给 LLM,让它能向用户解释"为什么没存"。拦截是给 LLM 的反馈,不是给程序的异常。

STEPS
05 / 10

三类钩子 + 两个新工具

  1. Before · 拦截型 — _hook_sensitive_guard:工具在保护名单 + 命中敏感词 → 直接 block
  2. Before · 改写型 — _hook_sensitive_masker:其余工具命中 → 参数打码(sk-demo-***)后放行
  3. After · 观察型 — _hook_audit_logger:不拦不改,把调用记录追加进 audit_log.jsonl
新工具(20 → 22)作用
list_hooks查看注册了哪些钩子(before/after 各几个)
view_audit_log回放最近 N 条操作审计记录

两类工具两种策略:save_user_profile / mcp_call_tool / send_message 等 6 个"落盘/外发"工具硬拦截,其余工具只打码——教学上一次演示 block 和 rewrite 两种 Hook 能力。

CODE
07 / 10

核心代码 · 工具循环里的挂载点

for tool_call in msg.tool_calls:
    fn_name = tool_call.function.name
    fn_args = json.loads(tool_call.function.arguments)

    # ↓ 本期新增:Before 钩子链(拦截 / 改写)
    blocked, fn_args, hook_note = run_before_hooks(fn_name, fn_args)
    if blocked:
        status = "blocked"                          # 工具压根不执行
        result = json.dumps({"error": "工具调用被 Before Hook 拦截,未执行",
            "hook": "sensitive_word_guard", "reason": hook_note, ...})
    else:
        status = "masked" if hook_note else "ok"       # 打码 or 原样
        result = execute_tool(fn_name, fn_args)          # 真正执行

    # ↓ 本期新增:After 钩子链(审计落盘)
    run_after_hooks(fn_name, fn_args, result, status, duration_ms)

HOOKS = {"before": [...], "after": [...]} 是注册表,run_before_hooks / run_after_hooks 按注册顺序执行钩子链——任何一个 Before Hook 拦截即短路返回。

教学要点:改写发生在执行前,所以工具"看到"的就是打码后的参数;审计发生在执行后,所以日志能记下 status 三态。位置决定职责。

WHY
08 / 10

为什么 Agent 需要 Hooks?

😖 没有 Hooks(裸奔)

提示注入诱导外发数据 → 照发不误

用户口述密钥 → 直接写进用户档案

安全规则散落在各工具函数里,改一处漏一处

出了事想回放 → 无凭无据

😌 有 Hooks(本期)

同一套安检策略,对 22 个工具统一生效

敏感词分级:落盘/外发拦截,普通工具打码

加策略 = 往 HOOKS 注册表加一个函数,核心零改动

audit_log.jsonl = Agent 行为的行车记录仪

前 11 期管"能力",本期管"约束"——生产 Agent 的分水岭。

MCP 把能力边界推到进程之外,Hooks 在边界上设卡。审计日志不是"成功日志"——blocked 的调用恰恰最值得记录:拦下了什么、为什么拦,都在里面。
