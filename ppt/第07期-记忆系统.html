PROBLEM
02 / 11

Alex 重启就忘 —— 会话内记忆的局限

第 03 期起有的:会话内 history

messages = [
  {system: ...},
  {user: "我习惯用 Python 3.12"},
  {assistant: "好的..."},
  ...更多对话...
]

✓ 上一句说什么
✓ 10 轮上下文

但 messages 只活在内存里,程序退出就清空

会话内记忆解决不了

  • 重启后 Alex 不记得我是张三
  • 重启后 Alex 不记得"用 Python 3.12"
  • 同时跑两个项目,Alex 不知道用户是谁
  • 历史被 trim 之后,前面聊的偏好没了

本质:短期记忆不能替代长期记忆

人脑也一样:你不会因为昨晚睡了,今天就忘了自己叫什么。Agent 需要不同时间尺度的记忆。

CONCEPT
03 / 11

三层记忆架构

层级介质写入时机生命周期引入期
短期 messages[] history 每轮实时 会话内(超轮截断) 第 03 期已有
长期 / 用户画像 templates/USER.md 偏好变更时(Agent 调工具) 永久,跨会话常驻 第 07 期新增
原始历史 memory/raw_history.jsonl 每轮对话落盘 append-only,可审计 第 07 期新增
压缩 LLM 摘要 超轮时自动 compact 会话内,替换早期消息 第 07 期新增

💡 对应人脑:短期=工作记忆(WM) · 长期=陈述性记忆(LTM) · 原始历史=事件日志

三层各司其职,组合起来就是 Agent 的"完整记忆系统"。

STRUCTURE

用户画像 · templates/USER.md

# 用户画像(User Profile)

## 基础信息
- 角色:张三,创业公司 CTO
- 技术栈:Python(主力)、TypeScript、Go(学习中)

## 稳定偏好
- 代码风格:类型注解完整、函数不超过 50 行
- Python 版本:3.12(全项目统一)
- 包管理:pip + venv,不用 poetry / uv
- 回答风格:简洁、直接,代码 > 长段文字

## 已知反偏好
- 不要 emoji 装饰代码注释
- 不要在回答末尾追加"还有什么需要帮忙的吗"

加载时机

启动时 load_user_profile() 读全文 → 追加到 system prompt 尾部

写入方式

Agent 调 save_user_profile 工具 → 按 section 替换章节内容

Agent 自己会改自己的画像:你说"我开始用 uv 了",它自动写进去。

三层记忆 · 一次完整生命周期

启动(第 1 步): load_user_profile() → 读 USER.md → 追加到 system prompt
system: "你是 Alex..." + "技能索引: weather..." + "# 用户画像..." ← 三层拼好,常驻

user: "我开始用 uv 了"
assistant: tool_calls=[save_user_profile("稳定偏好", ...)] ← Agent 自己改画像
↓ 执行: 重写 USER.md 的"稳定偏好"章节
tool: {"saved": "稳定偏好"} ← 长期记忆已写入磁盘
assistant: "好的,已记下,你以后的项目都用 uv。"

↑ 上面所有事件都是"产生即落盘"——append_and_persist 同步写 raw_history.jsonl
Ctrl-C 崩了也至少有上一轮的快照

下次启动: 重新读 USER.md → 你看到"uv"已在画像里 ← 跨会话生效

关键:短期回灌上下文,长期写文件持久化,原始历史 append 落盘——三者完全独立。

WHY
09 / 11

为什么需要三层而不是一层?

方案优点缺点
只用 messages(短期) 简单 重启即忘,无用户身份
只用 JSONL(全量) 永久 每轮全量回灌,token 爆炸
只用 USER.md(长期) 跨会话 丢失对话细节,无法审计
三层组合(本期) 各取所长 实现稍复杂

trim vs compact

  • trim(第 03 期):超 MAX_ROUNDS=10 → 直接丢弃早期
  • compact(第 07 期):超 COMPACT_THRESHOLD=8 → 用 LLM 压缩成摘要,保留最近 10 轮
  • trim 是有损丢弃,compact 是有损压缩——后者慢一点但保留关键信息

save vs append

  • save(本期):按 section 替换整个章节
  • 如果 append:"代码风格"会出现两个矛盾描述
  • 同主题只能有一个权威版本——这是结构化文档的常识

三种记忆的写入策略不同:短期是"覆盖",原始历史是"append",长期画像是"替换章节"。

    看最近几条 JSONL 落盘内容
  • 思考题 — save_user_profile 如果改成 append 会怎样?
