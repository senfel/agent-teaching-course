CONCEPT
02 / 10

内置工具 vs MCP 工具 —— 工具从"内置"到"外挂"

🔧 内置工具(第 05 期)

写死在 Agent 进程里的函数
get_current_time / calculate / ...

加工具 = 改源码 + 注册 schema + 重启

16 个工具 16 个 if,execute_tool 越来越长

🔌 MCP 工具(本期)

跑在外部服务器进程里的工具
Agent 通过协议"远程"调用

加工具 = 连一个服务器,代码零修改

别人写好、拿来就用,服务器升级 Agent 无感

MCP = Model Context Protocol,连接外部工具服务器的开放协议

类比 USB:没有 USB 之前,每个外设都要专用接口;有了 USB,键盘鼠标硬盘插上就能用。MCP 之于 Agent 工具,就是那把"通用插座"。

FORMULA
03 / 10

MCP 的通信公式

AGENT
客户端进程
⇄
stdio
stdin/stdout 管道
⇄
SERVER
工具服务器进程

每行一条 JSON-RPC 2.0 消息,带 id 配对请求与响应

stdio transport 是 MCP 的第一种传输方式:把子进程的 stdin/stdout 当"电话线",Agent 往 stdin 写请求,从 stdout 读响应,全程不用网络端口。生产环境还有 streamable HTTP 等远程传输。

STEPS
05 / 10

协议三步 + 四个新工具

  1. 握手 initialize — 互报身份与协议版本,回 initialized 通知
  2. 拿工具 tools/list — 服务器交出工具清单(名称 + 描述 + 参数 schema)
  3. 调工具 tools/call — 传工具名 + 参数 JSON,收回 content 结果
新工具(16 → 20)作用
list_mcp_servers查看有哪些服务器可连接
mcp_connect连接服务器(启动子进程 + 握手 + 拉清单)
mcp_list_tools看服务器提供哪些工具、要传什么参数
mcp_call_tool统一入口:server_id + tool_name + arguments

四个新工具和前 16 个完全平等——都走同一套第 05 期的工具循环。注意对比:第 05 期加工具是加函数,本期加工具是连服务器。

CODE
07 / 10

核心代码 · _McpConnection

class _McpConnection:
    def _initialize(self):
        result = self._request("initialize", {
            "protocolVersion": "2024-11-05",
            "clientInfo": {"name": "alex-agent-step11", ...},
        })
        # 握手完成,必须回 initialized 通知(MCP 规范)
        self._send({"jsonrpc": "2.0", "method": "notifications/initialized"})
        self.tools = self._request("tools/list").get("tools", [])   # 缓存工具清单

    def call_tool(self, tool_name, arguments):
        result = self._request("tools/call", {"name": tool_name, "arguments": arguments})
        texts = [c["text"] for c in result.get("content", []) if c.get("type") == "text"]
        return "\n".join(texts)  # 结果统一装在 content 数组里

_request() 带自增 id 发请求,只认 id 配对的那条响应;_send/_recv 就是"写一行 JSON / 读一行 JSON"。

教学要点:stdout 是"协议专线"——服务器的日志必须打到 stderr,混进 stdout 会污染协议流,客户端直接解析失败。

WHY
08 / 10

为什么 Agent 需要 MCP?

😖 没有 MCP(工具内置)

加能力 = 改代码 + 注册 schema + 重启

同事的工具要抄进自己项目

换供应商 = 工具函数推倒重写

工具越多 execute_tool 越臃肿

😌 有 MCP(本期)

加能力 = 在注册表加一条连接命令

别人写好、发布,你连上就用

换实现不换接口:协议保证对话不变

Agent 常年 4 个 MCP 工具,后方无限扩展

第 05 期 Function Call 解决"LLM 怎么表达调工具";MCP 解决"工具从哪来"。

前者是 Agent 与 LLM 之间的约定,后者是 Agent 与外部世界的约定。两个约定叠起来,Agent 的能力边界第一次跑到了自己的进程之外。

TRY IT
09 / 10

试一试 · 4 个实验

  • 跑 python code/step11_mcp.py,看两个自动演示:① 连接 → 列工具 ② 搜仓库 → 查详情 → 看 issue

    理解了裸流,再看 _McpConnection 就是把手工操作代码化
  • 把服务器的日志改成 print 到 stdout —— 观察客户端怎么崩,体会"协议专线"的重要性

💡 学完这一期,你能回答:为什么 MCP 服务器升级,Agent 可以一行代码不改?—— 因为协议没变。
