STREAMING
06 / 10

为什么是 SSE,不是 WebSocket

📡 SSE(本期)

单向:服务端 → 客户端

纯 HTTP,`text/event-stream`

`fetch` + `getReader()` 原生读

适合"AI 打字机":发一条,连续吐多个事件直到 done

🔌 WebSocket(不用)

双向:双方互相推

升级长连接协议

需 WebSocket API

对聊天反而重:用不上双向

核心坑:流式 tool_calls 的 id/name/arguments 是分片到达的 —— `stream.py` 按 `tc.index` 累积分片,攒齐再执行

CODE
07 / 10

核心代码 · 流式工具循环

# stream.py:与非流式孪生,唯一区别是"边生成边 yield"
while True:
    content_parts, tool_calls = [], {}   # index → {id,name,arguments}
    for delta, model_id in llm_call_stream(messages, tools=TOOLS):
        if delta.content:                     # 文本增量 → 立刻吐给前端
            yield {"event": "delta", "text": delta.content}
        for tc in (delta.tool_calls or []):   # 工具调用按 index 攒,别漏别错位
            s = tool_calls.setdefault(tc.index, {"id":"", "name":"", "arguments":""})
            s["name"] += tc.function.name
            s["arguments"] += tc.function.arguments
    if not tool_calls:
        yield {"event": "done", "text": "".join(content_parts).strip()}; return
    for slot in sorted_by_index(tool_calls):   # 攒齐 → 执行 → 回灌 → continue
        yield {"event": "tool_call", "name": slot["name"], ...}
        yield {"event": "tool_result", "result": _run_one_tool(...)}

`llm_call_stream` 与非流式 `llm_call` 只差 `stream=True` + `stream_options.include_usage`,路由、记账逻辑完全复用 —— 统一入口的纪律没被打破。

DOCKER
08 / 10

Docker:一次构建,处处可跑

# Dockerfile 分层缓存:依赖最稳放最前,改代码只重建最后一层
FROM python:3.11-slim
COPY requirements.txt /app/requirements.txt          # ① 依赖层(独立)
RUN pip install --no-cache-dir -r /app/requirements.txt
COPY code/step15_deploy/ templates/ skills/ mcp_servers/  # ② 运行时资源
CMD ["python", "-m", "step15_deploy"]           # ③ 默认起 Web

# docker-compose.yml:env 注入 API Key + memory 挂卷持久化
services:
  alex:
    build: .
    ports: ["8000:8000"]
    env_file: [".env"]              # API Key 不进镜像
    volumes: ["./memory:/app/memory"]   # 容器销毁记忆不丢

标准交付:`cp .env.example .env` → `docker compose up --build` → 打开 http://localhost:8000。改代码再 build,依赖层缓存命中、只重建源码层。
