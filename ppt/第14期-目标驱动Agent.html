目标驱动 Agent

G O A L  D R I V E N  A G E N T
15 期系列 · 第 14 期 · 2026

前 13 期我们一直在"你说一句,它做一句"。
这一期,给 Alex 一个模糊目标:"帮我优化这个仓库的 README",
它自己订契约、自己规划、自己打 checkpoint,直到验收达标或预算耗尽。

CONCEPT
02 / 10

被动应答 vs 目标驱动 —— 差在哪

🧾 被动应答(第 13 期及以前)

用户说一步,Agent 做一步

目标模糊 → 泛泛而谈("优化 README 可以从以下几方面…")

复杂任务要人盯着,一轮轮追问"然后呢"

没有停止条件:要么烂尾,要么烧钱

🎯 目标驱动(本期)

给一个模糊目标,还一份验收报告

先订契约:目标 + 可判定的验收标准 + 预算

外层控制循环自主推进多轮,用户只看 checkpoint

三种停止:达标停 / 受阻止损 / 预算封顶

Agent 缺的不是能力,是目标感

你让 ChatGPT"优化一下 README",它十有八九回你一篇正确的废话 —— 不是它没能力,是它不知道"做到什么程度算完成"。

FORMULA
03 / 10

目标契约的四要素

GOAL
做什么
+
CRIT
怎么算完成
+
BUD
预算几轮
+
STAT
当前状态

= 目标契约 GOAL_STATE

验收标准是灵魂:写"每条建议附理由"(可判定),不写"写得更好"(没法判定)。契约订立后,一切执行和自评都对照它 —— 它是循环的锚。

CORE LOOP
05 / 10

控制循环 · 一个循环套一个循环

  1. 订约(Phase 1) — Agent 调 set_goal,把模糊目标改写成"目标 + 验收标准 + 预算"
  2. 执行(Phase 2) — 外层塞控制指令 → 内层 chat_with_tools 用 TodoList/子代理/MCP 干活
  3. checkpoint — 每轮结束 Agent 必须调 check_goal,对照验收标准如实自评并落盘
  4. 判停 — 看契约状态:done 停(达标)/ blocked 停(止损)/ failed 停(做不成);预算跑完仍 in_progress → 强制 failed(封顶止损)
  5. 验收汇报(Phase 3b) — 循环结束后对照契约逐条交代"是否达标、产出在哪里" —— 模糊目标进去,一份验收报告出来

外层 run_goal_loop 管"推进和停止",内层还是第 05 期的工具循环管"这一轮怎么干活"—— 这是整个课程第一次出现双层循环:意志(LOOP)升级成了目标感(GOAL)。

CODE
07 / 10

核心代码 · 订约与自评

# ① 订契约:模糊目标 → 结构化验收单
set_goal(
    goal="产出本仓库 README 的逐节优化方案",
    success_criteria=[
        "方案覆盖 README 现有全部小节,逐节给出保留/修改/删除建议",
        "每条建议附理由",   # ← 可判定,不是"写得更好"
    ],
    max_rounds=3,                  # ← 预算:控制循环最多 3 轮
)

# ② 打 checkpoint:对照验收标准如实自评,状态决定循环去留
check_goal(
    assessment="第1条已达标;第2条还差'安装'一节的理由",
    new_status="in_progress",      # done / blocked / failed / in_progress
    evidence="优化方案已写到回复中,共 7 节",
)

set_goal 订的契约存进 GOAL_STATE,check_goal 每次自评更新状态机并追加 goal_log.jsonl。控制循环 run_goal_loop 只看契约状态决定继续还是停 —— 代码里没有一个"猜它做完没有"的 if,全部由 Agent 自己的自评驱动。

WHY
08 / 10

目标契约 vs TodoList —— 别混着用

📋 TodoList(第 08 期)

管一轮对话内的步骤顺序

回答:"这一轮先做什么后做什么"

停止条件:清单勾完(单轮内)

类比:施工排期表

🎯 目标契约(本期)

管跨轮次的完成判定

回答:"几轮之后,什么时候算完"

停止条件:验收达标 / 受阻 / 预算耗尽

类比:甲方验收单

两者配合:每轮用 TodoList 排步骤干活,用 check_goal 向"甲方"汇报

为什么必须可判定 + 预算?LLM 有"讨好型人格"(你问做完了吗,它倾向说做完了)和"无限卷"(你不说停它一直干)两个毛病 —— 契约是防讨好,预算是防烧钱。

TRY IT
09 / 10

试一试 · 4 个实验

  • 直接问"帮我优化这个 README"vs 输入"目标:帮我优化这个 README" —— 体会一个前缀,两种人生
    "目标:"前缀经分流器进入控制循环,自主推进;不带前缀时 Alex 会建议你加前缀,契约只生于控制循环
  • 等它 check_goal(in_progress) 后追问"你现在就算 done 了吧" —— 看它守不守如实原则
    验收标准就是防"讨好型人格"的锚,看它是坚持还是被你带偏
  • 给一个 2 轮干不完的目标(如"把 15 期课程全部复习一遍") —— 触发封顶止损 failed
    预算硬上限:跑满轮数仍 in_progress,控制循环强制打 failed checkpoint
  • 说"帮我把这个仓库部署到生产环境",打开 memory/goal_log.jsonl —— 回放一个 blocked 目标的卡点
    为第 15 期埋伏笔:契约挂进 Web 服务后,怎么跨 HTTP 请求继续跑?

💡 学完这一期,你能把任何模糊目标变成"契约 + 循环 + checkpoint"的自主任务,并且敢于放手 —— 因为预算封顶和受阻止损替你看着账本。
