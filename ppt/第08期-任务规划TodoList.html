FORMULA
03 / 10

三状态机 + 双约束:顺序 + 单 in_progress

⬚
pending
→
▶
in_progress
→
✓
completed

⚠ 约束 1(顺序):必须按 ID 顺序逐个推进,#1 做完才能开 #2,不能跳过。

⚠ 约束 2(单 in_progress):同一时刻只能有一个 in_progress,设新的自动退旧的。

两条约束共同强制:一条条往下执行,不跳过、不并行。

约束不是模型自觉遵守的,是工具层面强制执行的。模型想跳过 #1 直接开 #3?工具直接返回错误。想同时开两个?第二个调用自动把第一个退回 pending。这叫"用代码约束模型行为"。

WORKFLOW
05 / 10

TodoList 工作流 · 5 步

  1. 拆任务 — 收到复杂任务时,调 todo_create 拆成 3-7 个子任务(全 pending)
  2. 标记开始 — 调 todo_update(task_id=1, "in_progress"),开始做第一个
  3. 执行任务 — 可以调其他工具(get_current_time / calculate / load_skill),也可以直接回答
  4. 勾完成 — 做完后调 todo_update(task_id=1, "completed")
  5. 看进度 — 调 todo_list 确认进度,继续下一个

注入到 system prompt 里的"工作指南"(来自 templates/todo_guide.md),核心原则:每轮对话先查 todo_list,有 in_progress 任务就把用户输入当作该任务的补充信息,推进任务而不是闲聊。

注意工作指南不是"用户提出复杂任务时才触发",而是每轮对话都先查 todo_list。有 in_progress 就推进,没有就判断是否新任务。这解决了"用户补充信息时模型当成闲聊"的问题。

CORE CODE
07 / 10

核心代码:三个工具 + 双约束

# ① 创建任务(全部 pending)
def todo_create(tasks: list[str]):
    for content in tasks:
        _todo_list.append({"id": _next_todo_id(),
            "content": content, "status": "pending"})

# ② 更新状态(核心:双约束)
def todo_update(task_id: int, new_status: str):
    # 约束 1:顺序 —— 前面的任务必须全部完成
    if new_status == "in_progress":
        blocked = [t["id"] for t in _todo_list
                   if t["id"] < task_id and t["status"] != "completed"]
        if blocked: return f"顺序约束:前面还有未完成 {blocked}"
    # 约束 2:单 in_progress —— 自动退回旧的
    if new_status == "in_progress":
        for t in _todo_list:
            if t["status"] == "in_progress": t["status"] = "pending"
    target["status"] = new_status

# ③ 查看进度
def todo_list():
    return {"total": len(_todo_list),
        "pending": ..., "in_progress": ..., "completed": ...}

两条约束都是工具层面强制执行:约束 1 拦住"跳过",约束 2 拦住"并行"。即使模型想跳过或并行,工具直接返回错误。

注意约束 2 的实现——遍历所有任务,把已有的 in_progress 全部退回 pending。这不是"提醒模型",是"直接改状态"。模型没有选择权,工具替它做了决定。这就是"用代码约束模型行为"的核心。

HOW IT WORKS
08 / 10

TodoList 的三层架构

① 提示词层(软约束)— todo_guide.md 注入 system prompt,引导 LLM "每轮先查 todo_list,有 in_progress 就推进,需要用户信息就停下"

模型可能不遵守(软约束),但 99% 会跟随。拦不住"模型自己编内容标完成"。

② 工具层(硬约束)— todo_create / todo_update / todo_list 三个 Python 函数,双约束在这里硬编码

模型无法绕过:跳过 → 返回错误,并行 → 自动退回 pending。但拦不住模型编造任务内容。

③ 工具循环(第 05 期复用)— while True: LLM 决定调哪个工具 → 代码执行 → 结果塞回 messages → LLM 看结果决定下一步

模型是"驾驶员",工具是"车",提示词是"交通规则"。三层缺一不可。

这三层不是本期新发明的。提示词层是第 04 期引入的,工具循环是第 05 期建的,本期只是加了第 8-10 个工具和一段指南。累积式的好处:加能力=加工具+加提示词,核心循环一行没改。
